# tcp/: TCP and evaluation

| File | What it does |
|---|---|
| `tcp-loss-aware.{h,cc}` | `TcpLossAware`: extends `TcpCubic`; at each loss, computes features, classifies, and cuts cwnd only for congestion |
| `loss-classifier.h` | Interface to the trained model |
| `generated-tree.cc` | The trained decision tree as C++. **Generated by `ml/export_tree.py`**; don't edit by hand |
| `../common/loss-features.*` | Feature extractor (shared with logging) |
| `../eval/plot_results.py` | Plots from `results/summary_*.csv` |

## Modes (`--classifier`)

- `cubic`: every loss is congestion (identical to CUBIC); used to collect training data
- `oracle`: uses the simulator's ground truth; the best result any classifier could reach
- `tree`: uses the trained decision tree

## Design

- Timeouts (RTO) are always treated as congestion.
- Losses classified as random multiply cwnd by `RandomLossBeta` (default 1.0 = no cut).
- **Safety fallback** (`tree` mode only): after more than `MaxConsecutiveRandom` random
  decisions in a row, if the smoothed RTT is above `FallbackSrttRatio` x min RTT and still
  rising, the loss is treated as congestion anyway.
- **Growth during random-loss recovery:** ns-3 does not grow cwnd during recovery, so
  TcpLossAware grows ssthresh at CUBIC's pace instead; PRR and the cwnd = ssthresh rule at
  recovery exit turn that into window growth. The pre-loss ssthresh is restored afterwards.
